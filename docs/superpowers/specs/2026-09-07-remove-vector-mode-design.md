# 벡터 스케치 모드 제거 설계

## 목표

현재 앱에서 벡터 스케치북 기능과 그 전용 구현을 제거하고, 이미 생성된 벡터 스케치북·캔버스·브러시 데이터를 로컬과 Firebase에서 영구 삭제한다. 비트맵 스케치북, 그림일기, 공유 스케치북과 최근 버그 수정은 그대로 유지한다. 과거 Git 커밋으로 저장소 전체를 되돌리지 않고 현재 `master`에서 벡터 하위 시스템만 앞으로 제거한다.

## 사용자에게 보이는 결과

- 새 스케치북 UI에서 벡터 생성 버튼과 벡터 생성 단계를 제거한다.
- 홈·목록·상세·읽기·편집 화면에서 벡터 배지, 미리보기와 벡터 편집기 진입 경로를 제거한다.
- SVG 브러시 가져오기, Basic/Art/Pattern, 패스 선택·이동·크기·회전, Fill/Stroke, SVG 내보내기를 제거한다.
- 업데이트 후 기존 벡터 스케치북은 목록에서 사라지며 복구할 수 없다.
- 비트맵 스케치북, 페이지 PNG, 표지, 다이어리, 사용자 설정과 공유 스케치북 데이터는 유지한다.

## 제거 범위

### 앱 기능과 코드

- `app/src/main/java/com/g1/sketchbook/vector`의 벡터 편집·렌더·저장·SVG 코드 전체
- `app/src/test/java/com/g1/sketchbook/vector`와 벡터 전용 통합 테스트
- `VectorDocumentPersistenceCoordinator`와 해당 테스트
- `Sketchbook`, 생성 마법사, 목록·홈·라우팅의 `vector`, `vectorInfinite`, `vectorCanvasW`, `vectorCanvasH` 분기
- 백업 모델·저장소·동기화의 `vectorCanvas`, `vectorCanvasV2`, `stampBrushes` 처리
- 벡터 모드에서만 사용되는 SVG 갤러리 저장 API와 벡터 전용 아이콘 코드

Android의 일반 UI 아이콘에 쓰는 Compose `ImageVector`, XML VectorDrawable 및 `vectorDrawables` 빌드 설정은 벡터 스케치 기능과 무관하므로 유지한다. 사용자가 따로 보관 중인 미추적 디자인 원본 `image/icon/vector.svg`도 앱 데이터가 아니므로 건드리지 않는다.

## 로컬 데이터 영구 삭제

일반 저장소가 책 목록을 읽기 전에 작은 호환 정리기에서 기존 JSON을 직접 검사한다.

1. `g1_sketchbooks` SharedPreferences의 `books` 배열에서 `vector == true`인 항목의 ID만 수집한다.
2. 해당 항목을 배열에서 제거하고 `filesDir/sketchbooks/{id}` 디렉터리 전체를 삭제한다. 이 디렉터리에 있는 `vector_canvas.json`, `vector_canvas_v2.json`, 복구 후보, 미리보기 등도 함께 삭제된다.
3. `filesDir/vector_brushes`, `filesDir/vector_brushes_v2`와 `g1_stamp_brushes` SharedPreferences를 삭제한다.
4. `vector == true`가 명시된 항목만 삭제한다. 누락·손상·알 수 없는 메타데이터는 비트맵 데이터 보호를 위해 삭제 대상으로 추정하지 않는다.
5. 같은 정리를 여러 번 실행해도 결과가 같은 멱등 작업으로 만든다.

## Firebase 데이터 영구 삭제

로그인 사용자의 일반 백업 동기화보다 먼저 원격 정리를 실행한다.

- `/backups/{uid}/sketchbooks/{bookId}/meta/vector == true`인 책은 `/backups/{uid}/sketchbooks/{bookId}` 전체를 삭제한다.
- `/backups/{uid}/stampBrushes` 전체를 삭제한다.
- 삭제가 실패한 원격 벡터 책은 로컬로 복원하지 않고 다음 로그인·동기화 때 정리를 재시도한다.
- 계정별로 실행하므로 여러 Google 계정을 사용했다면 각 계정으로 로그인할 때 해당 계정의 벡터 데이터가 삭제된다.
- 구버전 앱이 다른 기기에서 다시 벡터 데이터를 업로드할 수 있으므로, 새 버전은 인증된 동기화 때마다 남아 있는 벡터 데이터를 다시 제거한다. 사용자는 모든 기기를 새 버전으로 업데이트하거나 구버전 앱을 제거해야 한다.

Firebase 정리 코드는 구형 데이터의 위치를 식별하고 삭제하기 위한 최소 호환 코드만 남긴다. 벡터 문서를 파싱하거나 렌더링하지 않는다.

## 순서와 실패 처리

1. 앱 시작 시 로컬 벡터 데이터를 먼저 정리한다.
2. 로그인 상태이면 원격 벡터 데이터를 정리한다.
3. 원격 정리가 끝나거나 네트워크 오류로 연기된 뒤 일반 비트맵·다이어리 백업 동기화를 진행한다.
4. 원격 삭제 실패는 비트맵 데이터 동기화를 막지 않지만, 원격 벡터 항목은 항상 필터링해 재다운로드하지 않는다.
5. 삭제 대상 판별이나 파일 삭제 중 오류가 나면 비벡터 항목을 건드리지 않고 다음 실행에서 재시도한다.

## 대안 검토

- 과거 태그로 전체 롤백: 이후 추가된 다이어리 복구와 UI 수정까지 잃으므로 사용하지 않는다.
- UI만 숨기기: 코드와 데이터가 남고 사용자의 영구 삭제 요청을 충족하지 못하므로 사용하지 않는다.
- 현재 코드에서 선택 제거: 다른 기능을 보존하면서 벡터 하위 시스템만 제거할 수 있어 채택한다.

## 테스트와 완료 조건

- 로컬 정리 테스트: 벡터 책/브러시는 삭제되고 비트맵 책·페이지·표지·다이어리는 바이트 단위로 유지된다.
- 손상 메타데이터 테스트: `vector == true`가 확실하지 않은 데이터는 삭제하지 않는다.
- 멱등성 테스트: 정리기를 여러 번 호출해도 예외나 추가 삭제가 없다.
- 원격 정리 계약 테스트: 현재 UID의 벡터 책과 `stampBrushes`만 삭제하며 다른 사용자의 경로와 일반 책은 선택하지 않는다.
- 동기화 테스트: 원격 삭제 실패 중에도 벡터 책이 로컬로 부활하지 않는다.
- 정적 확인: 앱 소스·테스트에 벡터 UI/렌더/저장 진입점이 남지 않는다. 일반 `ImageVector`와 VectorDrawable은 제외한다.
- 전체 단위 테스트, `assembleDebug`, `lintDebug`와 `local.properties` 없는 깨끗한 소스 빌드를 통과한다.
- versionCode 148, versionName 2.18.0으로 새 태그를 만들어 GitHub Release APK를 배포하고 실제 다운로드 가능 여부를 확인한다.

## 비가역성

이 버전을 실행하고 Firebase 정리가 성공하면 기존 벡터 스케치북·캔버스·브러시는 복구할 수 없다. 삭제는 사용자가 명시적으로 승인한 범위이며, 비트맵·다이어리·공유 데이터에는 적용하지 않는다.
