# 벡터 캔버스 폐곡선 채우기 설계

## 배경 및 목적

지금 벡터 캔버스의 "채우기" 토글(`VectorStroke.fillEnabled`)은 획 자체를 리본(진행 방향에 수직으로 굵기만큼 오프셋한 폴리곤) 모양으로 만들어 그 폭만큼 solid color로 채우는 것 — 일러스트레이터의 path fill/stroke 개념을 그대로 포팅한 것이다(v2.14.0, 브레인스토밍 없이 바로 구현됨). 그런데 사용자가 실제로 원하는 "채우기"는 이것과 전혀 다르다: **손으로 닫힌 도형(원, 8자, 소용돌이 등)을 그리면 그 도형의 내부 영역이 자동으로 solid color로 채워지는 것** — 색칠 공부/flood-fill에 가까운 개념이다. 리본 폭을 채우는 지금 방식은 얇은 펜으로 그리면 "테두리(윤곽선)만 있고 안은 안 채워진 것"처럼 보여서, 사용자가 실기기에서 이를 렌더링 버그로 오인해 리포트하는 계기가 됐다(실제로는 개념 자체가 다른 것이었음).

이 스펙은 "채우기"의 의미를 폐곡선 내부 채우기로 재정의하고, 그 판정·렌더링 방식을 정한다. UI는 이번 스펙에서 최소한으로만 손보고(기존 토글 재사용), 전체 UI 개편은 사용자가 명시적으로 범위 밖으로 뺐다(별도 후속 작업).

## 동작 정의

- **판정 대상**: 지금 그리고 있는 **한 획**(손가락 담기~떼기, 하나의 `VectorStroke`) **안에서** 그 획의 중심선이 **자기 자신과 교차**하는 경우만 본다. 서로 다른 여러 획이 합쳐져서 만드는 닫힌 영역은 이번 스펙 범위 밖 — 채우지 않는다.
- **실시간**: 손을 떼야 판정하는 게 아니라, 그리는 도중 교차가 발생하는 그 순간 바로 그 구역이 채워진다(라이브 프리뷰에도 적용).
- **여러 교차**: 한 획 안에서 자기 교차가 여러 번 생기면(소용돌이, 8자 등) 각 닫힌 구역을 전부 독립적으로 채운다.
- **선(리본)은 항상 보임**: 채우기 on/off와 무관하게 펜이 그은 리본(기존 `strokeOutline` 모양) 자체는 항상 그려진다 — "채우기"는 그 위에 닫힌 구역을 추가로 채우는 것이지, 리본을 대체하는 게 아니다. (기존에는 `fillEnabled=false`면 리본 자체가 안 그려졌는데, 이 동작은 없어진다 — 리본은 무조건 그려짐.)
- **채우는 영역의 기준**: 획의 중심선(각 점을 이은 폴리라인, `VectorPoint.x/y`)이 자기 자신과 교차해서 만드는 폐곡선을 채운다 — 리본의 두께(내부 겹침)까지 고려한 정밀한 경계가 아니라, 중심선 기준의 단순한 폐곡선이다(사용자가 그리는 대부분의 닫힌 도형에서 리본 두께는 전체 넓이에 비해 작아 체감 차이가 거의 없고, 계산이 훨씬 단순해진다).

## 채움 색

- 리본(선) 색과 별도로 채움 전용 색을 고를 수 있다.
- 기본값은 리본과 같은 색 — 채우기를 켜고 채움 색을 따로 안 고르면 리본 색 그대로 채워진다. 원하면 다른 색으로 바꿀 수 있다.

## 데이터 모델

```kotlin
data class VectorStroke(
    val color: Long,
    val points: List<VectorPoint>,
    val cap: VectorCap = VectorCap.BUTT,
    /** 의미 변경: "리본을 채울지"가 아니라 "이 획이 자기 자신과 교차해서 만드는 닫힌 구역을
     *  자동으로 채울지". true여도 자기 교차가 없으면(대부분의 획) 시각적으로 아무 효과 없음 —
     *  리본 자체는 이 값과 무관하게 항상 그려진다. */
    val fillEnabled: Boolean = true,
    /** 닫힌 구역을 채울 색 — null이면 [color](리본 색)를 그대로 쓴다. [fillEnabled]=false면 무시. */
    val fillColor: Long? = null,
    val strokeColor: Long? = null,
    val strokeWidthPx: Float = 2f,
    val brushProfileId: String? = null,
)
```

`fillEnabled` 필드 이름과 저장 위치는 그대로 재사용(하위호환 JSON 파싱 로직 그대로 유지, 기본값 `true`도 유지) — 의미만 위와 같이 바뀐다. `fillColor`는 새 옵션 필드로 추가(기존 `strokeColor`와 같은 패턴: null이면 "기본값 사용").

## 알고리즘

새 순수 Kotlin 함수를 `StrokeGeometry.kt`에 추가한다(기존 `strokeOutline`/`contentBounds`와 같은 파일, 같은 "렌더링 시점마다 매번 계산하는 순수 함수" 패턴 — 저장 데이터에 미리 구운 값이 아니므로 옛날 저장 파일도 마이그레이션 없이 새 방식으로 자동 렌더링됨):

```kotlin
fun selfIntersectionFills(points: List<VectorPoint>): List<List<Point>>
```

- 점 목록을 순서대로 훑으면서, 매 세그먼트(점 i→i+1)마다 그 이전의(인접한 세그먼트는 제외) 아직 안 쓰인 세그먼트들과 교차하는지 표준 2D 선분-선분 교차 판정으로 확인한다.
- 세그먼트 i가 더 앞의 세그먼트 j와 교차하면, 그 교차점부터(세그먼트 j의 교차 좌표) 세그먼트 i의 교차 좌표까지 사이에 있는 점들(`points[j+1..i]`) + 두 교차 좌표를 이어 닫힌 다각형 하나를 만들어 결과 목록에 추가한다. 그다음엔 세그먼트 j 이전 구간은 이미 이 다각형에 다 쓰였으니 건너뛰고, 세그먼트 i 이후부터 계속 같은 방식으로 훑어서 다음 교차를 찾는다 — 그래서 소용돌이처럼 교차가 여러 번 있어도 겹치지 않게 각 구간이 한 번씩만 다각형이 된다.
- 교차가 전혀 없으면(대부분의 획) 빈 목록. 8자 모양처럼 시작점과 상관없는 위치에서 한 번만 교차하면, 그 교차 이후 구간(교차점으로 돌아와 닫히는 한쪽 고리)만 닫힌 걸로 잡힌다 — 교차 이전 구간(아직 안 닫힌 쪽)은 원래 안 닫혀 있으니 채워지지 않는 게 맞는 동작이다.

`VectorRenderer.drawVectorPage`(그리기 중 프리뷰 + 커밋된 획 렌더링 + 썸네일 렌더링이 전부 공유하는 함수)에서, 스탬프 브랜치 다음·기존 리본 렌더링 코드에 다음을 추가한다:
1. 리본(`strokeOutline`)은 지금처럼 무조건 그린다(그리고 `stroke.strokeColor`가 있으면 그 위에 테두리도 지금처럼).
2. `stroke.fillEnabled`면 `selfIntersectionFills(stroke.points)`로 닫힌 구역들을 구해서, `stroke.fillColor ?: stroke.color`로 각각 채워 그린다(리본 위에 덧그림).

라이브 프리뷰(그리는 중인 `current` 점 목록)에도 커밋된 획과 똑같이 이 로직이 적용되므로(같은 `drawVectorPage` 경로를 재사용하는 기존 구조 그대로), 손을 떼기 전에도 교차가 생기는 순간 자동으로 채워진 모습이 보인다 — 별도의 "실시간 감지" 코드를 손 인식(터치 이벤트) 쪽에 추가할 필요 없이, 매 프레임 다시 그릴 때 이미 있는 점 목록으로 다시 계산하는 것만으로 충분하다(기존에도 프리뷰가 매 `invalidate()`마다 다시 그려지는 구조라서 자연스럽게 맞아떨어짐).

SVG 내보내기(`vectorPageToSvg`)에도 같은 방식으로 적용 — 리본 `<path>` 뒤에 닫힌 구역마다 `<path>`를 추가로 써서 `fillColor`로 채운다.

## UI

이번 스펙에서는 최소한만 손본다(전체 UI 개편은 범위 밖, 후속 작업):
- 기존 "브러시 설정"(톱니바퀴) 메뉴의 "채우기" 토글을 그대로 재사용 — 의미만 위처럼 바뀐다.
- 토글이 켜져 있을 때, 그 아래 채움 색을 고르는 스와치 한 줄이 추가로 나타난다(안 고르면 리본 색 기본 사용) — 기존 "획" 다이얼로그의 테두리 색 선택 UI와 같은 패턴(즐겨찾기 색상 목록 재사용).

## 이번 스펙에서 다루지 않는 것

- 서로 다른 여러 획이 합쳐져서 만드는 닫힌 영역 채우기(지우개/캔버스 전체 flood-fill 등) — 한 획 안의 자기 교차만.
- 리본 두께까지 고려한 정밀 경계 채우기 — 중심선 기준 단순 폐곡선.
- 브러시 설정/획 다이얼로그를 포함한 벡터 캔버스 툴바 UI 전체 개편 — 사용자가 명시적으로 "일단 기능부터" 요청, 범위 밖.
- 스탬프 브러시로 그린 획의 자기 교차 채우기 — 스탬프 획은 `brushProfileId`가 있으면 지금처럼 스탬프 렌더링 경로를 그대로 타고, 이 폐곡선 채우기는 일반 펜 획(`brushProfileId == null`)에만 적용.

## 테스트

- `selfIntersectionFills`는 순수 Kotlin(Android 의존 없음)이라 유닛 테스트 대상: 교차 없는 획(빈 목록), 단순 루프 하나(원처럼 시작점 근처로 돌아오는 획), 8자 모양(교차 2개, 닫힌 구역 2개), 소용돌이(교차 여러 개) 등.
- 선분 교차 판정 자체도 순수 함수로 분리해서 개별 테스트(평행선, 교차하는 두 선, 안 만나는 두 선, 끝점만 스치는 경우).
- 렌더링/UI(`VectorRenderer.kt`, `VectorCanvasScreen.kt`, `VectorSvgExport.kt`)는 이 프로젝트 관례상 컴파일 확인 + 수동 확인.
