# 색상 라이브러리 설계

## 배경 및 목적

지금 색상 시스템은 두 계층으로 나뉘어 있다: 툴바에 항상 보이는 즉시선택 즐겨찾기(5색,
`SessionStore.quickFavorites`)와 "팔레트" 버튼을 누르면 뜨는 21색 그리드(`SessionStore.paletteColors`,
`BrushControls.kt`의 `FavoritesGridPopup`). 21색은 고정된 단일 리스트라서 사용자가 색 조합을
용도별로 나눠 관리할 방법이 없다.

이 스펙은 21색 팔레트를 "라이브러리" 여러 개 중 3개를 골라 합친 것으로 재구성한다 — 라이브러리
하나는 색상 7개짜리 묶음이고, 사용자가 이름을 붙여 최대 30개까지 만들 수 있다. 그중
정확히 3개를 선택하면 그 7색×3 = 21색이 지금의 "팔레트" 역할을 대신한다. 즉시선택 즐겨찾기는
5개에서 3개로 줄어든다(라이브러리와는 독립적인 기존 방식 그대로 유지).

## 데이터 모델

```kotlin
data class ColorLibrary(
    val id: String,
    val name: String,
    val colors: List<Long>, // 항상 정확히 7개
)
```

- `SessionStore`에 새로 추가:
  - `libraries: List<ColorLibrary>` — 로컬 파일(JSON, `SketchbookRepository`/`StampBrushRepository`가
    쓰는 것과 같은 손수 직렬화 관례) + prefs에 id 목록 순서 저장.
  - `activeLibraryIds: List<String>` — 팔레트를 구성하는, 정확히 3개(또는 그 미만 — 아직 3개를
    못 채웠을 때) 라이브러리의 id를 **선택한 순서대로** 저장. 팔레트의 1/2/3번째 7색 묶음 순서를
    결정한다.
  - `paletteColors`(기존 21색 flat 필드)는 삭제한다 — 이제 팔레트는 `activeLibraryIds`가 가리키는
    라이브러리 3개의 `colors`를 순서대로 이어붙인 파생값이라, 별도로 저장하지 않는다(단일 진실
    공급원은 라이브러리들 자체).
  - `quickFavorites`는 그대로 유지하되 개수만 3개로 바꾼다: `QuickFavoritesCount = 5` → `3`. 저장된
    값의 크기가 안 맞으면(기존 5개 데이터 포함) 자동으로 기본값으로 대체되는 기존 로직을 그대로
    재사용 — 마이그레이션 코드 불필요.
- `PaletteCount`(21) 상수는 유지하되 이제 "라이브러리 3개 × 7색"의 파생값(3 * `LibraryColorCount`)임을
  문서화한다. 새 상수: `const val LibraryColorCount = 7`, `const val MaxLibraries = 30`,
  `const val ActiveLibraryCount = 3`.

## 기존 데이터 처리

사용자 결정: 기존에 저장돼 있던 21색 팔레트 데이터는 그대로 버린다. 앱 업데이트 후 첫 실행 시(또는
`libraries`가 비어 있을 때) 기본 라이브러리 3개를 자동 생성한다 — 각 이름은 "라이브러리 1"/"라이브러리
2"/"라이브러리 3", 색상은 지금 코드에 있는 `DefaultFavorites`(21색) 리스트를 7개씩 순서대로 나눠
채운다. 이 3개를 만들자마자 `activeLibraryIds`에 그 순서대로 넣어 기본 팔레트로 선택해 둔다 — 그
결과 사용자 눈에는 지금과 똑같은 21색 팔레트로 시작하는 것처럼 보인다(내부적으로만 라이브러리
구조로 바뀜). 즐겨찾기(quickFavorites)도 개수만 3개로 바뀌고 기존 5개 저장값은 크기 불일치로 자동
무효화되어 새 기본값(3개)으로 시작한다.

## 라이브러리 관리

- **개수 상한**: 30개. 그 이상은 "새 라이브러리" 버튼이 비활성화되고 이유를 안내.
- **생성**: 이름을 입력받아(기본값 "라이브러리 N", N은 지금까지 만든 개수+1) 새 라이브러리를 만든다.
  처음 7색은 `DefaultFavorites`의 앞 7개를 복사해서 시작(전부 같은 색이 아니게) — 만들자마자 바로
  색상을 편집할 수 있다.
- **색상 편집**: 라이브러리를 열면 그 안의 7개 스와치가 보이고, 하나를 누르면 색상 피커가 떠서 그
  자리만 바꿀 수 있다(지금 팔레트 편집과 같은 상호작용).
- **이름 변경**: 언제든지 가능.
- **삭제**: 언제든지 가능. 삭제한 라이브러리가 `activeLibraryIds`에 들어 있었다면 그 자리는 빈
  자리가 된다(팔레트가 14색 또는 7색으로 줄어듦 — 아래 "선택 개수가 3 미만일 때" 참고).
- **팔레트 구성(3개 선택)**: 라이브러리 목록에 체크박스가 있고 최대 3개까지 체크할 수 있다. 이미
  3개가 체크된 상태에서 새로 하나를 체크하면 **가장 먼저 선택했던 것**이 자동으로 해제된다(선입선출).
  체크 해제도 언제든 가능. 선택한 순서가 곧 팔레트의 1/2/3번째 7색 묶음 순서다.
- **선택 개수가 3 미만일 때**: 라이브러리를 아예 안 만들었거나(있을 수 없음 — 첫 실행에 3개 자동
  생성) 활성 라이브러리를 삭제해서 1~2개만 남은 경우, 팔레트는 선택된 만큼만(7색 또는 14색) 보여준다
  — 21칸을 억지로 채우려 하지 않는다.

## UI

기존 "팔레트" 버튼(`BrushControls.kt`)을 누르면 뜨던 21색 그리드 팝업(`FavoritesGridPopup`)을
라이브러리 관리 화면으로 바꾼다:
- 라이브러리 목록(이름 + 체크박스 + 그 라이브러리의 7색 미니 미리보기), 각 항목을 탭하면 그
  라이브러리의 7색 편집 화면으로 들어감(이름 변경·삭제 버튼도 그 화면에).
- 목록 맨 아래 "새 라이브러리 추가" 버튼(상한 도달 시 비활성화).
- 이 화면과 별개로, 실제 캔버스에 색을 고르는 21색 그리드(지금 `FavoritesGridPopup`이 보여주던 것)는
  "선택된 3개 라이브러리의 색을 순서대로 이어붙인 목록"을 그대로 그린다 — 그리기 화면에서 색을
  직접 고르는 흐름 자체는 지금과 똑같이 유지되고, "팔레트 편집" 버튼을 눌러야 라이브러리 관리
  화면으로 들어간다.

## 동기화

라이브러리 목록과 `activeLibraryIds`를 계정 백업에 포함한다 — 스탬프 브러시 목록에 이미 쓰인
것과 같은 툼스톤 기반 리스트 동기화 패턴을 그대로 따른다(원격에만 있는 라이브러리는 받아서 추가,
원격에서 지워진 건 로컬에서도 삭제, 로컬에만 있거나 원격이 더 오래된 건 로컬을 원격에 올림).
`activeLibraryIds`(어떤 3개가 선택됐는지)는 기존 설정 동기화(`RemoteSettings`, last-write-wins
방식)에 새 필드로 추가한다.

## 이번 스펙에서 다루지 않는 것

- 라이브러리 안 색상 개수를 7개가 아닌 다른 값으로 바꾸는 기능(항상 고정 7개).
- 라이브러리를 공유하거나 다른 사용자와 주고받는 기능.
- 팔레트를 구성하는 라이브러리 개수를 3개가 아닌 다른 값으로 바꾸는 옵션(항상 고정 3개).
- 기존 21색 팔레트 데이터의 실제 마이그레이션(사용자 결정: 버리고 기본값으로 리셋).

## 테스트

- `SessionStore`의 라이브러리 CRUD·활성 목록 계산(선입선출 3개 제한, 상한 30개)은 로직 자체를
  순수 함수로 뽑을 수 있는 부분(예: "활성 라이브러리 3개의 색을 순서대로 이어붙이기", "체크 시
  선입선출로 밀어내기")은 유닛 테스트 대상으로 분리한다.
- 로컬 파일 저장/로드, Compose UI, Firebase 동기화는 이 프로젝트 관례상 컴파일 확인 + 수동 확인.
